# Danish Node integration status

The three service workflow has been exercised locally through the WP3 orchestrator
and through Solution Studio: prompt input reaches `BuildRunConfig`, which writes a
JSON run configuration; `GenerateTopology` writes candidate topology JSON; and
`RenderTopologies` writes a JSON drawing index and four SVG images for the
CHP at 310-D to dumpload at 716-D example. The observed configuration contained
the requested terminals and no warnings. These are onboarding smoke observations,
not formal T3.3 test results.

The `web_ui` and Ollama containers are auxiliary and are not orchestrator nodes.
The UI's `/confirm` endpoint records a selected signature only in process memory:
it is not a durable decision, a pause/resume step, or an instruction to actuate
physical equipment. Rejection does not automatically rerun the workflow.

The generator uses an embedded SYSLAB model, not live plant telemetry. It limits
enumeration to the first `how_many` (default 20) candidates before ranking; the
recommended candidate is not guaranteed to be globally optimal. The current
service call does not pass `max_extra_pipes` or `load_topology` from the run
configuration to the enumerator. Check the parsed configuration's `warnings`
field to distinguish LLM extraction from fallback to default terminals.

All three services must share the named Docker volume `denmark-node-data` at
`/data`. A separate Studio API deployment must mount this volume read-only and
set `ARTIFACT_BASE_PATH=/data` to preview the generated SVG files. Prompt input
and SVG preview are supported in Studio's development branch; the Danish UI's
confirmation step is not yet integrated with Studio or WP3 execution.

The `export/` directory and `export.zip` are generated by
`./generate-export.sh` and intentionally excluded from version control.
